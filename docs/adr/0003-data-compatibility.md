# ADR 0003 — data compatibility with the TypeScript app

Status: accepted (2026-10-31)

## Context

Users already have data: a SQLite file on desktop and IndexedDB in the browser, plus KML/KMZ files that round-trip through the old app.
A rewrite that cannot open that data, or that silently changes field semantics, is a regression regardless of how good the renderer is.

## Decision

Keep the wire and disk formats identical.

- **SQLite**: the same schema (`folders`, `placemarks`, `styles`, `screen_overlays`, `schema_migrations`, same indexes, `SCHEMA_VERSION = 2`), and the same JSON-in-a-`data`-column layout.
- **Serde naming**: `#[serde(rename_all = "camelCase")]` everywhere, with `skip_serializing_if = "Option::is_none"` so absent optionals stay absent rather than becoming `null`.
- **Patch semantics**: TypeScript's `Partial<T>` treats `undefined` as "unchanged" and `null` as "clear". Rust cannot express that with `Option<T>`, so updates use `Patch<T>` (`Unset | Set(T)`), and optional fields use `Patch<Option<T>>` where `Set(None)` clears. This is covered by a contract test.
- **Identifiers and times**: UUID v4 (`uuid` with the `js` feature for wasm) and RFC 3339 with milliseconds and `Z`, matching `crypto.randomUUID()` and `toISOString()`.
- **Number formatting**: JavaScript's `toFixed` rounds exact decimal ties away from zero; Rust's formatter rounds ties to even. `terra-core::units` implements the JS behaviour and is validated against goldens generated by running the TypeScript code (`tools/parity/extract-fixtures.mjs`).
- **KML**: the same `terra-globe:` ExtendedData keys and the same lossless Circle/Rectangle round-trip.

## Consequences

- Migration is a file copy, not a data transformation: the desktop app probes for the old Tauri database and copies it into the new location on first run.
- Every adapter must pass `terra_storage::contract::run`, including the in-memory one.
- Parity is verified by differential fixtures rather than by re-deriving expected values by hand, so a drift shows up as a failing test with the TypeScript output in the message.
